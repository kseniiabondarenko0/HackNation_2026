# RADAR INNOWACJI — план v2 (усиление PROJECT_PLAN.md)

Оригинальный план остаётся базой. Здесь только изменения, которые повышают баллы по 5 критериям PCI (по 20%) и снижают риск. Всё привязано к тексту задания «Pełna treść zadania konkursowego».

## 1. Что меняем и почему

| # | Изменение | Зачем (пункт задания / критерий) |
|---|---|---|
| 1 | **Ручная форма «Zgłoś innowację» + ввод URL** в основе, рядом с авто-сбором | Задание: «zgłaszanie *lub* automatyczne wykrywanie». Страховка демо при недоступных сайтах; стоит ~1 ч |
| 2 | **Три явные «ścieżki»** вместо общего «следующий шаг»: rozwój / transfer / komercjalizacja / wdrożenie, выбор по правилам, с обоснованием | Задание: «rekomendowanie dalszej ścieżki…» — это формулировка пункта дословно |
| 3 | **Похожие решения (TF-IDF) переносим из P1-C в основу** | Задание: «ograniczanie ryzyka dublowania prac». Дёшево (sklearn, без LLM), заметно жюри |
| 4 | **Профили получателей + сопоставление** (типы учреждений, потребности, теги) вместо «только тип получателя» | Задание: «łączenie twórców z użytkownikami, partnerami, inwestorami». Только кандидаты по профилю, без обещаний согласия |
| 5 | **Прозрачная рубрика оценки**: 5 критериев 0–3 + «brak danych», веса в конфиге; «полнота доказательств» и «потенциал» раздельно; общий индикатор только для сортировки | «ocena według jasno określonych kryteriów», «porównywać potencjał». Без псевдо-вероятностей |
| 6 | **LLM — за адаптером, демо не зависит от LLM**: backends `ollama` / `openai_compat` / `rules`; результаты кэшируются в БД и воспроизводимы | Qwen3:4b на польском — главный риск; Ollama доступна только на Mac |
| 7 | **SQLite (WAL) вместо PostgreSQL** на хакатон | Нет установки и Docker; один worker; уникальные ограничения и транзакции те же. Postgres — в «после хакатона» |
| 8 | **Сквозная трассировка требований → экран → слайд** (раздел 2) | Критерий 1 и 4: жюри видит каждый пункт задания в демо |

Отклонение от инструкций проекта (Next.js/SQLite): остаёмся на Django, как решила команда — стек знаком, нужны скрапинг, очередь и локальная LLM на Python; Django admin даёт CRUD источников бесплатно. БД — SQLite, как в инструкциях.

## 3. Рубрика оценки (прозрачная, в конфиге)

Критерии (каждый: 0–3 или `brak danych`): **Problem** (ясна ли проблема), **Dowody** (подтверждено ли существование/применение), **Wyniki** (есть ли результаты), **Przenośność** (описаны ли условия переноса), **Gotowość** (idea→prototyp→pilotaż→użytkowane).
- «Полнота доказательств» = доля критериев не `brak danych` и с проверенной цитатой.
- «Потенциал» = взвешенная сумма только по известным критериям, с указанием, сколько критериев неизвестно. Мало данных ≠ низкая ценность: показываем отдельно.
- Правила пути: stage=idea/prototype + публичный автор → *rozwój*; locally_used/pilot + Przenośność≥2 → *transfer/wdrożenie*; есть результаты + рыночный сигнал (патент/заказчик) → *komercjalizacja*. Любой путь сопровождается «чего не хватает».
